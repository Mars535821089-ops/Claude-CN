### Cowork — native-equivalence finding and minimum adapter

The native `yukon-silver-config` provider's `y2r()` getter reads one shared
`autoCompactWindow` and has no session argument. HostLoop `_H()` propagates that
shared value into `CLAUDE_CODE_AUTO_COMPACT_WINDOW`. A real-source getter fixture
demonstrates that different synthetic session arguments receive the same value,
and a config refresh replaces it. Thus it is **not equivalent to the existing
explicit session allowlist**, even before runtime/lifecycle acceptance.

The minimum 5.x-specific HostLoop hook is pinned to
`.vite/build/index.chunk-2cjcenUp.js`, owner `i`, logger `t.MTt`, and the unique
SDK-options anchor. It uses the unchanged existing `cowork_compaction_policy.cjs`
adapter, packaged as `.vite/build/claude-cn-compaction-policy.cjs`.

It is **unconfigured and inactive by default**. Only an explicitly supplied
`CLAUDE_CN_SESSION_COMPACTION_POLICY` path enables policy loading at session
spawn. This build does not set that environment variable, create a real policy,
read a current policy, or embed any real session IDs. Future maintenance must
review/migrate the desired private policy separately, without putting real
session data into a public external build directory.

The adapter preserves per-session allowlists, other SDK settings/env values,
model/provider/effort selections, file-based settings refusal, managed/native
disable preferences and failure-to-native fallback. Synthetic execution tests
cover listed/unlisted sessions, disabled native compaction, unavailable policy
module and unchanged default behavior. It does not change model capacity or
add an 80/90 policy. Existing adapter window validation is unchanged; it is not
a claim about any provider's actual context capacity. Real compaction remains
unverified until an authorized app/route test.
