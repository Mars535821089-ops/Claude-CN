- `.claude/relay-cards` → 现有 iCloud `ClaudeRelay/relay-cards`。目标新增/修改仍改变指纹。
- 已观察到的 gstack、指定 `.agents/skills` 和指定 npm `.bin` 链接。链接文本与目标元数据都保护；精确目标匹配、内部二级别名也单独校验。未知链接/改向/特殊项拒绝。

本次实际扫描未发现现存Singleton IPC或其他socket/FIFO，不能把原始失败泛称为IPC故障。IPC支持仅限两个Claude用户数据根下明确的 Chromium Singleton 协议：用户所属、Darwin用户临时目录中的 `.org.chromium.Chromium.*/SingletonSocket` 必须真是socket；Cookie/Lock须为无持久目标的配套链接。**不读取Cookie/Lock的nonce文本**，持久目标改向与任意其他IPC拒绝。

仅排除两个Claude根目录直属的 `Cache`、`Code Cache`、`GPUCache`、`DawnGraphiteCache`、`DawnWebGPUCache`、`GPUPersistentCache`、`GraphiteDawnCache`、`Crashpad`，以及精确的诊断文件/别名。full-06随包Electron框架含上述缓存和Singleton名称，真实目录类型也已只读观察；缓存内部未知链接/特殊项仍拒绝。不会以 `**/Cache` 泛化到会话目录。排除不是删除、移动或恢复这些文件。

目录自身mtime/ctime不再单独算新用户代次：包含的普通孩子仍逐项记录，因此新增文件、新schema、改名、权限/类型或inode变化仍捕获。保留用户设置、历史、会话、Cowork策略和所有Keychain文件的元数据保护；未把`.fl`、`.sb`、数据库WAL等仅凭名字视为可忽略临时文件。

## 恢复材料究竟是什么

入口自动生成标准材料，**不要求手造`.enc`文件或声称覆盖全部数据的JSON**：

- `previous.app`：当前旧应用的完整副本，签名与整包哈希验证。
- `protected-state.json`：自动计算的受保护根、元数据指纹和规则版本；不含文件正文或凭据。
- `recovery.json`：自动生成的schema 2清单，绑定真实挂载UUID、代次、旧应用及元数据清单哈希。
- 安装过程中追加 `install-receipt.json` 和仅含locale原字段差异的journal，600权限。

这些材料位于**已核实的加密PrivateArchive卷**，目录700/文件600。它是“应用回退＋本入口locale差异回退＋元数据保护证据”，**不是会话/凭据/Keychain灾备副本**。不会从旧快照恢复任何业务数据。schema升级或新用户数据出现时，拒绝旧应用自动回滚，保留当前应用、最新数据及旧应用副本，进入人工协调。若维护方案另要求全量业务数据灾备，应使用既有授权备份能力单独完成，不能把本材料冒充为那种备份。

准备时不退出应用；复制期间旧应用或被保护状态变化会报错，不写成功清单，保留失败材料，不覆盖前代。失败重试选新空私密代次目录，不删除用户链接/资料。

## 可执行步骤：先只读，授权后才有副作用

以下命令为交接步骤，**本轮没有在真实环境执行其中的grant/prepare apply/install/rollback**。统一维护授权尚待用户回答，父级须先取得对应授权，不能把文档当作授权。无须重建或下载full-06。

```sh
cd '/Users/mars/projects/Claude软件完整汉化'
PY=/opt/homebrew/bin/python3
PR="$HOME/Library/Application Support/Mars Storage Maintenance/PrivateArchive"
R="$PR/claude5-$($PY -c 'import uuid; print(uuid.uuid4().hex)')"

# 1. 只读准备计划：检查已有挂载、候选、当前应用及元数据；不创建R。
PYTHONDONTWRITEBYTECODE=1 "$PY" scripts/install_51231.py --recovery "$R" --prepare-recovery

# 2. 获用户维护授权并审阅上一步plan_sha256后，生成15分钟准备权限。
# PREP_SHA为刚审阅的plan_sha256，不是密文，也无需手写JSON。
PYTHONDONTWRITEBYTECODE=1 "$PY" scripts/install_51231.py --recovery "$R" --prepare-recovery --grant --apply --expected-plan "$PREP_SHA"

# 3. 准备旧应用副本与标准元数据材料；不退出/启动应用，不复制凭据正文。
PYTHONDONTWRITEBYTECODE=1 "$PY" scripts/install_51231.py --recovery "$R" --prepare-recovery --apply --authorization "$R/authorize-prepare.json"

# 4. 只读安装预检，审阅新的plan_sha256。
PYTHONDONTWRITEBYTECODE=1 "$PY" scripts/install_51231.py --recovery "$R"

# 5. 获准退出/交换/启动且审阅INSTALL_SHA后生成权限；本步仍不退出应用。
PYTHONDONTWRITEBYTECODE=1 "$PY" scripts/install_51231.py --recovery "$R" --grant --apply --expected-plan "$INSTALL_SHA"

# 6. 仅在授权维护窗口执行：先同卷复制和完整复核，再退出、原子交换、启动一次。
PYTHONDONTWRITEBYTECODE=1 "$PY" scripts/install_51231.py --recovery "$R" --apply --authorization "$R/authorize-install.json"
```

普通 `--apply` 没有匹配权限文件不会自授权。权限绑定操作和完整计划SHA，15分钟到期；复制后、退出前、交换前、启动前重验。`--grant --apply` 本身是需已获用户授权的显式操作者动作，不会自动OAuth或延展维护授权。计划变化须重新审阅；未到期权限不会被静默覆盖。

入口不从外盘 `os.replace` 到`/Applications`。先ditto到`/Applications`同卷新暂存目录，验证完整字节/模式/链接、签名、ASAR和st_dev；Darwin `renameatx_np(RENAME_SWAP)`单次原子交换。旧应用保留在同卷暂存位置，私密副本也保留。不覆盖真实settings/session/policy/Keychain，只在应用停止后对已有配置的locale字段做条件更新；已有中文值不改。locale恢复要匹配本入口写入的哈希，用户后来编辑则拒绝覆盖。

启动提交前落盘回执，`launch_count=1`，重复apply/结果未知不再启动；只确认新PID加载的可执行inode和固定包身份，结果仍是 `started_pending_acceptance`，不是GUI通过。

### 条件回滚

```sh
# 只读：新用户编辑、会话、凭据元数据或schema变化会在退出之前拒绝。
PYTHONDONTWRITEBYTECODE=1 "$PY" scripts/install_51231.py --recovery "$R" --rollback
# 仅审阅ROLLBACK_SHA且获相应授权后：
PYTHONDONTWRITEBYTECODE=1 "$PY" scripts/install_51231.py --recovery "$R" --rollback --grant --apply --expected-plan "$ROLLBACK_SHA"
PYTHONDONTWRITEBYTECODE=1 "$PY" scripts/install_51231.py --recovery "$R" --rollback --apply --authorization "$R/authorize-rollback.json"
```

退出候选时若又保存新数据，仍会拒绝交换并持久记录 `manual_recovery_required`。成功回滚停留在 `rolled_back_stopped`，不第二次启动，不还原旧数据库/用户目录。
