## P1：locale 校验后的竞争写会被整文件覆盖

位置：`scripts/install_51231.py:381-389`，尤其`:387-388`；调用者
`apply_locale:391-406` 与 `restore_locale:408-418` 均共用该函数。

```python
if file_hash(path)!=before: raise ValueError(...)
os.replace(temp,path)
```

第二次哈希检查与替换不是一个条件交换。如果其他写者在检查完成后、replace系统
调用前更新config，replace仍无条件删除该新版本，写入先前加载的整份JSON，而不只
是locale。`:451-453` 随后重算baseline，反而把覆盖后的状态当成当前基准。
退出Claude不等于用户/其他配置写者都停止；自己的recovery锁也不约束这些写者。

### 确定性合成复现（已执行）

使用现有 `tests/test_install_51231.py::Install5Tests`，原生进程/挂载/应用交换仍是
公开fixture的mock；仅在真正替换locale文件的边界插入另一份合成用户编辑：

```python
import sys, json
from pathlib import Path
from unittest.mock import patch
sys.path.insert(0, 'tests')
from test_install_51231 import Install5Tests
c = Install5Tests(); c.setUp()
try:
    token = c.token()
    real_replace = c.m.os.replace
    def competing_replace(src, dst):
        if Path(dst) == c.config and Path(src).name.startswith('.locale-'):
            c.config.write_text('{"locale":"fr-FR","other":"new-user-choice"}')
        return real_replace(src, dst)
    with patch.object(c.m.os, 'replace', side_effect=competing_replace):
        result = c.run_install(apply=True, authorization=token)
    print(result['phase'], json.loads(c.config.read_text()), c.native.events)
finally:
    c.doCleanups()
```

Python3.14.7、`-B`、`PYTHONDONTWRITEBYTECODE=1`；临时目录由fixture创建并清理。
结果：

```text
started_pending_acceptance
{"locale":"zh-CN","other":"keep"}
["copy","quit","exchange","start"]
```

新用户的`other`与locale均丢失，流程仍启动一次候选。原来的“后来编辑拒绝覆盖”
测试仅覆盖最后检查之前的变动，没有覆盖syscall边界。此入口不备份配置正文，
因此不能声称可从它的元数据恢复包找回被覆盖内容。

建议：不要用增加一次哈希检查冒充原子CAS。采用保留displaced版本的原生原子交换
并验证确切preimage/父目录身份，冲突时保留双方、记录manual且不得继续启动；或采用
经证明能协调全部写者的机制。locale回退同样要受保护。不应盲目把旧JSON换回去，
否则可能再次覆盖更晚编辑。应新增上述边界回归，保留原字段/locale断言。

## P2：准备复制可在挂载消失后重建缺失父目录

位置：`prepare_recovery:347-350`、`preparation_plan_after_copy:367-370`、
`Native.copy:528-531`。mount检查在复制前的计划阶段及复制后的检查中；实际复制
仅验证路径无链接和目的不存在，并未把目标父目录dev/inode绑定为已核实加密卷。
ditto会自动创建缺失父目录。

已用同一公开fixture模拟“权限已核验/锁已取得，复制边界PrivateArchive被移出路径，
原挂载点变为空目录，mount状态变为不可用”：

```text
failure=ValueError
fallback_recovery_dir_recreated=true
fallback_previous_app_written=true
success_manifest_written=false
events=["copy"]
```

模拟仅在临时fixture内rename目录，不是真的卸载/断开任何卷。另对纯合成源目录
调用`Native.copy`，确实创建了原先不存在的`missing-parent/recovery`并复制fixture
文件，验证不是只因mock实现与ditto不同。

影响：后置校验会拒绝成功，且不退出/启动应用，故不把它升级成数据丢失P1；
但真实挂载点消失后可能在底层内置路径留下未授权的恢复副本/目录，违背断盘不回退
写入的要求。当前测试只覆盖开始前未挂载、UUID不符等，不覆盖复制边界的父目录消失。

建议：复制及后续写入需锚定已核实、已存在的父目录（dev/inode/挂载身份），拒绝
自动递归重建恢复父目录；用目录fd等方式避免把消失的挂载路径重新解析到另一卷。
错误处理也不能为写failure记录重建底层目录。断盘复现不应靠删除/搬迁真实配置通过。

### 原P1：actual displaced保留、manual与不启动

- `locale_write:482-518`不再做哈希后无条件replace。0700保留目录先有intended副本，
  `_swap_at:507`执行fd版原生交换后，`:508-513`比较**实际被交换出的文件**正文及
  dev/inode/mode/uid/gid/size/mtime/nlink身份，另核对当前文件就是拟安装版本。
  不匹配抛LocaleConflict并保留双方；没有“再交换一次旧JSON回去”的覆盖动作。
- `apply_locale:533-537`把保留位置放入locale journal，竞争错误继续向安装事务传播；
  `install:599-610`对LocaleConflict明确禁止自动应用交换回退，落manual回执，不进入
  launch_submitted/start分支。它是保留现场待人工协调，不应表述成竞争用户编辑必然
  仍留在config原路径；真正的syscall-boundary编辑保存在displaced文件中。
- `restore_locale:539-550`也使用同一locale_write；回滚竞争同样保留actual displaced和
  rollback intended，`rollback:622-640`转manual，不第二次启动应用。
- 新增测试`:488-506`确在交换边界写入另一份完整合成配置，断言新用户字段和拟写入版本
  都还存在，安装manual且无start，回滚manual且累计start仍为1。没有修改原字段断言
  或以仅检查最后哈希的方法制造通过。

### 原P2：复制/回执绑定原目录，不补建替代路径

- `BoundDir:86-129`逐组件O_NOFOLLOW打开现存目录，绑定dev/inode；计划write_roots也
  绑定写入根身份。`locked:445-467`持锁期间持有真实根/恢复目录fd；创建恢复叶目录
  是已绑定父fd下的单级mkdirat，没有递归创建挂载点/替代父目录。
- `Native.copy:660-675`先独占创建目标叶目录，再把该目录fd传给子进程；preexec只
  fchdir到该fd，ditto目标固定为`.`。复制后复核父/目标/写入根身份，拒绝路径替换。
- `durable:143-165`通过原parent.fd创建临时文件、replace及fsync；正常写前/后检查
  路径身份。脱离路径时manual写入只尝试原卷fd，**不mkdir/重新解析新位置**。
  强制卸载使原fd也不可写时仍可能无法持久记录，这个边界没有被假装消除。
- 新测试`:508-528`覆盖复制边界“原private树改名＋原路径空目录替代”的场景，
  断言新路径为空、没有新recovery、原树fd收到manual且未quit；缺失父目录的Native.copy
  也必须拒绝，不能依赖ditto递归补建。
